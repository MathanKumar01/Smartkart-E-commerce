1. Project Overview

SmartCart is a full-featured e-commerce web application built with Django. It allows users to browse products (laptops, phones, accessories), add items to a cart or wishlist, place orders, and manage their account. The project is hosted on Render with a PostgreSQL database and Cloudinary for media storage.

4. All Errors Encountered & Fixes

Error 1 — Database Connection Drops During Import

❌ psycopg2.OperationalError: server closed the connection unexpectedly

Where: backend/import_products.py while importing 1,544 products.

What it means: The remote Render PostgreSQL server closed the TCP connection mid-operation. This happens because Render's free-tier PostgreSQL has a connection timeout, and importing thousands of rows takes long enough that idle connections are killed between rows.

Why it matters: Without handling this, any row after the dropped connection would fail silently or crash the import.

✅ Fix: Retry Logic with Connection Reset

Wrapped every Product.objects.create() in a retry loop. On failure, it calls close_old_connections() (Django utility that discards stale connections and forces a fresh reconnect on the next query), then retries up to 3 times.

from django.db import close_old_connections
from django.db.utils import OperationalError, InterfaceError

def create_product_with_retry(payload, max_retries=3):
    for attempt in range(1, max_retries + 1):
        try:
            Product.objects.create(**payload)
            return True
        except (OperationalError, InterfaceError) as exc:
            close_old_connections()       # reset stale connection
            if attempt == max_retries:
                print(f"DB error after {max_retries} retries: {exc}")
                return False
            print(f"Retrying (attempt {attempt + 1}/{max_retries})...")

Error 2 — Product Detail Page Returns 500 (Blank Screen)

❌ psycopg2.OperationalError: could not translate host name "dpg-...render.com" to address — Name or service not known

Where: Any page that hits the database (product detail, dashboard) when running locally.

What it means: The DATABASE_URL environment variable points to a Render-hosted PostgreSQL server. When Django tries to connect to that server from your local machine, Windows DNS cannot resolve the Render subdomain — because it is only accessible from within Render's network.

Why it matters: Every database query fails → blank/error page for every product click.

✅ Fix: Automatic SQLite Fallback via DNS Check

Added a _build_default_database() function in settings.py. It tries socket.gethostbyname(host) before trusting DATABASE_URL. If DNS resolution fails and DEBUG=True, it silently falls back to a local SQLite file — so local development works with zero config changes.

import socket

def _build_default_database():
    if DATABASE_URL:
        parsed = dj_database_url.parse(DATABASE_URL, conn_max_age=600)
        host = parsed.get("HOST")
        try:
            if host and host not in {"localhost", "127.0.0.1"}:
                socket.gethostbyname(host)   # DNS check
            return parsed                    # DNS OK → use Render DB
        except socket.gaierror:
            if DEBUG:
                print("WARNING: Remote DB unreachable. Using SQLite.")
                return {
                    "ENGINE": "django.db.backends.sqlite3",
                    "NAME": BASE_DIR / "db.sqlite3",
                }
    return { ... }   # local PostgreSQL fallback

DATABASES = {"default": _build_default_database()}

Error 3 — Slow Page Load (1500+ Products)

❌ Products page taking 3–5 seconds to load

Where: backend/products/views.py

What it means: The original view used Product.objects.all() which loaded all 1,500+ product rows — including large description text fields — into memory at once. The template then rendered every single card. Additionally, the splash screen had a hardcoded 1500ms JavaScript delay.

✅ Fix: Pagination + .only() + set() + Reduced Splash
# views.py — before
products = Product.objects.all()

# views.py — after
products = Product.objects.only(
    "id","name","description","price","original_price",
    "discount_percent","rating","image_url","category"
).order_by("id")

cart_products = set(                        # O(1) lookup instead of O(n)
    Cart.objects.filter(user=request.user)
    .values_list("product_id", flat=True)
)

paginator = Paginator(products, 24)         # 24 items per page
page_obj = paginator.get_page(request.GET.get("page"))

Splash screen JS delay reduced from 1500 → 200 ms.

Error 4 — WhiteNoise Not Serving Static Files in Production

❌ CSS / JS files returning 404 after deploy

Where: backend/smartcart/settings.py — MIDDLEWARE list

What it means: WhiteNoise must be placed immediately after SecurityMiddleware (position 2). It was placed last in the list, after all other middleware. Django processes middleware top-to-bottom; if WhiteNoise is last, static file requests pass through every other middleware first — and in production some of those middlewares would reject or not handle static paths, returning 404.

✅ Fix: Move WhiteNoise to Position 2
MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "whitenoise.middleware.WhiteNoiseMiddleware",   # ← must be 2nd
    "django.contrib.sessions.middleware.SessionMiddleware",
    "django.middleware.common.CommonMiddleware",
    "django.middleware.csrf.CsrfViewMiddleware",
    "django.contrib.auth.middleware.AuthenticationMiddleware",
    "django.contrib.messages.middleware.MessageMiddleware",
    "django.middleware.clickjacking.XFrameOptionsMiddleware",
]

Also removed the duplicate SecurityMiddleware that had been accidentally added at the bottom.

Error 5 — SECRET_KEY Exposed in Source Code

❌ Hardcoded SECRET_KEY = "django-insecure-lpk7@..."

What it means: Django's SECRET_KEY signs session cookies, CSRF tokens, and password reset links. If anyone reads your source code (public GitHub repo), they can forge session tokens and impersonate any user — including admins.

✅ Fix: Read from Environment Variable
SECRET_KEY = os.getenv("SECRET_KEY", "django-insecure-fallback-for-local-only")

Set a strong random SECRET_KEY in Render's Environment settings before deploying.

Error 6 — DEBUG=True in Production

❌ DEBUG = True hardcoded

What it means: When DEBUG=True in production, Django shows full stack traces — including file paths, environment variables, and settings values — to anyone who triggers an error. This is a major security risk.

✅ Fix: Read from Environment Variable
DEBUG = os.getenv("DEBUG", "True") == "True"
# On Render: set DEBUG=False

Error 7 — build.sh Using Old JSON Fixture (Wrong Schema)

❌ loaddata backend/data.json fails after new fields added

Where: backend/build.sh

What it means: The old data.json fixture was created before the model was extended with rating, original_price, discount_percent, and reviews_count. Loading it into the new schema either fails or inserts products with all new fields as null/0.

✅ Fix: Replace fixture load with CSV importer
# build.sh now runs:
python backend/import_products.py --delete-existing

# Only imports if no products exist (or FORCE_SEED=1 on Render)

Error 8 — Image URLs Not Parsed Correctly from CSV

❌ Image field contained JSON array strings like ["https://...","https://..."]

Where: smartkart_products_clean.csv — image column

What it means: The CSV was generated by a scraper that stored all product images as a JSON-encoded list. Storing the raw string as image_url showed the array literal in <img src> instead of the actual URL.

✅ Fix: Parse JSON array and extract first URL
import json

raw = str(row.get("image", "")).strip()
try:
    urls = json.loads(raw)
    image_url = urls[0] if isinstance(urls, list) and urls else raw
except (json.JSONDecodeError, ValueError):
    image_url = raw.strip("[]'\" ")

10. Final Deploy Checklist

Before Pushing to GitHub

  • ✅ DEBUG = False set via env var on Render
  • ✅ SECRET_KEY in Render environment (not in code)
  • ✅ smartkart_products_clean.csv is committed to repo (needed by build.sh)
  • ✅ Migration 0005 is committed
  • ✅ ALLOWED_HOSTS includes your Render domain
  • ✅ CSRF_TRUSTED_ORIGINS includes your Render URL

On Render Dashboard

  • ✅ Set SECRET_KEY environment variable
  • ✅ Set DEBUG=False
  • ✅ PostgreSQL add-on is attached and DATABASE_URL is set
  • ✅ Cloudinary vars set (CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, CLOUDINARY_API_SECRET)
  • ✅ Build command: bash backend/build.sh
  • ✅ Start command in Procfile: cd backend && gunicorn smartcart.wsgi:application

After First Deploy

  • ✅ Check deploy logs — should see "Imported products: 1544"
  • ✅ Visit site and click a product — detail page should load
  • ✅ Register a new user and test cart & orders
  • ✅ Check /admin/ with a superuser
💡 To re-seed products on Render at any time:
Set FORCE_SEED=1 in Render environment, trigger a manual deploy, then remove the variable.
